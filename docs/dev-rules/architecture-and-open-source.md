# 架构与开源复用规则

触发：新依赖、公共模块、接口、技术替换或自研通用能力。依据为 [系统架构](../design/system-architecture.md)、[技术比较](../engineering/technology-selection.md)和[统一接口](../design/integration-contracts.md)。

## 开源选择流程

A 先比较：业务适配、维护与发布、目标平台、许可/分发、集成复杂度、退出成本。记录官方 URL、查询日期、版本、归档/维护证据和未证实项；不能以 star 数或发布日期单项结论代替适配判断。稳定老库不自动淘汰，快发版也不自动可信。

同功能、同目标环境且许可适配时，优先最近功能提交/发布更活跃的方案；查 GitHub 默认分支 commit、pushed_at、release 与必要的近期频率。updated_at 不等于代码更新时间，不同功能库不按日期互替；本地源码位置和参考范围只进本机索引。

B 使用 A 的材料实施 spike，锁定兼容版本、工具链和传递依赖，保存功能/失败/打包证据；安装成功不算验收。上游主分支文档可能领先已发布版本，API 签名以锁定包及同版本说明为准。

按“上游配置/现成 API → 薄适配 → 最小隔离补丁 → 经记录的替换/自研”处理缺口。每个上游问题进入 [集中事项台账](../decisions/open-questions.md) 的 OSS 项，包含复现、版本、影响、临时方案、移除条件和下次复核。提上游 issue/发送消息按会话授权处理，不默认代用户对外沟通。

D-08 已授权参考 Codex 官方 Rust 源码自研窄模型客户端与上下文整合，边界见 [模型客户端](../design/rust-model-client.md)；通用网络/序列化/流解析继续复用开源。普通已选依赖版本兼容调整可由 B 完成；改变 Rust/GPUI 方向、金融语义、用户能力、不可兼容数据或长期新运行时必须给具体方案并集中决定。未经确认的候选可以隔离验证，不能写成已获人批准。

## 依赖方向与数据所有权

- 领域核心不依赖 UI、数据库驱动、模型客户端或网络；适配器实现宿主定义的窄接口。
- UI、AI、批处理调用同一应用服务。统一 DTO、错误、权限、数据版本和取消语义，不按前端或模型供应商复制业务逻辑。
- 首期模块化单体，按需要建 crate/worker；没有当前消费者不预建插件系统、消息总线或远程服务。
- SQLite 为业务事实与 Rust 会话状态的主存储；会话转录不是金融真相，模型传输不拥有业务或会话仓储。
- 数值、行情复权、训练时钟和未来可见性不能交给图表库或 LLM 自行决定。

依赖升级按影响重跑领域/协议/打包样本。锁定和 license inventory 是要求；完整许可证核验和漏洞扫描结果只有实际运行后才能声明。
