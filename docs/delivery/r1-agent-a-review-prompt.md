# R1：B → A 审核 prompt 模板

历史交接：2026-10-07 起当前执行入口为 [M0 v1.0 当前计划](stage-plan.md)。下文保留原审核/回归依据，不用于重启旧返工；当前 amend 规则以合并计划为准。

由 B 完成后使用真实版本填充方括号字段再交用户；尚无符合本版计划的交付证据，本文不代表审核已发生。

```text
你是 DELTA 的 Agent A，负责 R1 集中审核。B 的交付分支是 [实际分支]，最终 commit 是 [完整 SHA]，报告是 docs/evidence/r1-delivery.md，未提交改动/归属为 [实际情况]。唯一原计划为 docs/delivery/r1-execution-plan.md v1.1，必要用例为 docs/delivery/r1-cases.json。

先读 AGENTS.md、REVIEW.md、当前状态、有效决定和集中台账，对照真实代码与 B 证据检查 32 项 P0 和必要技术门槛；不要只复述报告。核对测试基点/源码指纹，复用仍有效的证据，重点验证金额/幂等/更正、范围/快照、Rust 双协议/流式终态/部分流不重放与工具白名单、压缩/恢复、取消晚到事件、伪造引用和备份恢复。模拟、真实服务、人工检查分别判断。

在本轮内直接修复明确局部问题并做定向验证，按 D-09 amend 当前 R1 阶段提交，保持阶段父提交；不要新增逐问题修复 commit 或 amend 文档框架提交。核对 B 提供的旧 SHA 与现场新 SHA/源码指纹，保留已有修复。返工 B 也继续 amend 同一阶段，交接必须给新的完整 SHA；较大或跨模块缺口完成独立审核后一次性列出稳定 F 编号、触发/预期/依据、位置、修复验收及需保留的 A 修复，再输出 B 可直接执行的整批返工 prompt。不要逐发现交回，不把实现缺口交用户人工验收。

输出 docs/evidence/r1-review.md（创建并登记）或明确独立的审核记录，更新当前状态和集中台账，给出工程实现、A 技术审核、S0/S1 产品验收三项结论。需要人的事项提供稳定包、从根执行的真实命令、隔离数据准备、步骤/预期/日志和重测边界。最后推荐一个明确下一步并提供对方 prompt；没有下一轮计划时不要直接要求 B 开始无限范围开发。不得自动 push、PR、合并或发布。
```

返工继续同一计划与问题编号，B 逐条补修复/验证，A 复核关闭。报告中的测试基点与最终 commit 分别记录，避免自引用提交循环。
