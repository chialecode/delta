# DELTA 产品需求文档

版本 0.2 · 2026-09-26 · 保留原需求编号；增加上下文状态与统一能力约束。已确认和默认值见 [决定记录](../decisions/confirmed-decisions.md)，实际交付见 [当前状态](../delivery/status.md)。

## 1. 产品定位

DELTA 是个人金融活动的管理与分析桌面工作台。产品以可信的资产账本为基础，把市场观察、交易决策、执行记录、历史训练、策略实验和 AI 复盘连接起来。

名称含义：Delta 表示资产与市场的变化；Evaluation 表示收益风险与策略评估；Ledger 表示账本；Training 表示历史训练；Analyzer 表示分析工具定位。

核心闭环：观察市场 → 形成判断 → 训练或交易 → 记录决策 → 解释结果 → 改进下一次决策。

## 2. 用户与价值

主要用户是拥有一个或多个投资账户、投资美股/ETF/加密现货、希望了解资产变化并改善交易决策的个人投资者。次要用户是进行日线策略研究的轻量量化使用者。

| 场景 | 当前困难 | DELTA 的交付价值 |
| --- | --- | --- |
| 资产分散 | 多账户、多币种，余额增加不等于赚钱 | 统一估值、资金流与损益解释 |
| 交易复盘 | 图表、成交和笔记分散 | 从一笔成交恢复当时的决策上下文 |
| 盘感训练 | 容易提前看到答案，成本假设不真实 | 隐藏未来的可复现训练与执行评估 |
| 规则研究 | 有想法，但缺乏完整执行规则 | 条件扫描、统一回测与基准比较 |
| 数据积累 | 记录很多，难以发现重复问题 | 引用个人证据的 AI 分析 |

## 3. 范围与阶段

| 阶段 | 必需范围 | 完成标准 |
| --- | --- | --- |
| S0 技术验证 | 桌面、图表、存储、离线数据、指标与数据源验证 | 关键不确定性有实际验证结论 |
| S1 第一版/P0 | CSV 账本、资产估值、历史日线、指标、交易笔记、只读 AI 复盘、备份导出 | 一个真实账户完成导入、核对、分析与追溯 |
| S2 训练/P1 | 隐藏未来、模拟委托、费用预设、训练记录与报告 | 训练可恢复、重放、比较 |
| S3 策略/P1 | 条件组合、日线扫描、Python 策略、回测、实验比较 | 同一输入可重现结果，可作样本外评估 |
| S4 扩展/P2 | 更多接口与周期、节点图、复杂资产 | 按独立需求逐项交付 |

S1 覆盖美股、ETF、加密现货。手工现金、其他资产和负债可纳入净资产展示，但未经专门建模的资产只支持手工估值，不承诺完整交易收益分析。

S1 支持账户 CSV 导入、手工记账和行情数据接入；券商/交易所账户 API 自动同步列为 P1。行情来源不足时允许用户导入 OHLCV 文件，但发布验收仍要验证美股和加密现货各一个可用数据路径。

不属于 S1–S3：真实下单、策略自动实盘运行、期权定价、保证金和强平、永续资金费结算、DeFi 拆解、税务申报、社交跟单、多设备自动同步。数据模型保留扩展点，界面不展示尚不可用的承诺。

## 4. 基本产品原则

1. 数据本地保存，离线仍能访问已下载行情、账本和笔记。
2. 先回答“变化来自哪里”，再呈现复杂指标。
3. 实盘记录、模拟训练和回测实验独立存放，不能混入真实净资产。
4. 计算结果明确范围、币种、时间、费用、数据来源和完整度。
5. 不完整或无法计算的结果显示原因；不以零或编造数据代替。
6. AI 通过同一套确定性分析能力获取结果，并提供可打开的证据。
7. 优先复用活跃开源能力，自研聚焦方案整合、金融语义、数据关联、AI 上下文状态与统一对接接口。

## 5. 功能需求

### 5.1 设置、账户与数据导入

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-BASE-01 | P0 | 创建本地资料库，设置界面时区、报表币种和数据目录 | 重启恢复设置；改变报表币种不改变原始交易 |
| FR-BASE-02 | P0 | 配置银行、券商、交易所、钱包、手工账户及统计组合 | 账户可加入多个分析组合；同一组合中不重复计入 |
| FR-DATA-01 | P0 | CSV 字段映射、预览、校验和分阶段导入 | 预览展示原始行、规范化值、错误和疑似重复；确认后事务提交 |
| FR-DATA-02 | P0 | 幂等、来源追溯和纠错 | 同一文件重导不重复入账；可追溯批次；更正后可重建统计 |
| FR-DATA-03 | P0 | 历史行情与汇率下载或文件导入 | 展示来源、覆盖范围、更新时间、复权和缺失区间 |
| FR-DATA-04 | P1 | 只读账户 API 同步余额、成交与现金流 | 分页/限流可恢复；同步游标在数据提交后推进；有对账差异列表 |
| FR-DATA-05 | P0 | 人工余额与账本余额对账 | 差异显示数量、币种、时点；不自动覆盖历史来凑平 |

CSV 模板至少定义：账户、事件类型、发生时间和时区、标的标识、方向、数量、价格、计价币种、费用及费用币种、来源 ID。字段依事件类型适用；缺失成本或期初记录进入待补全状态。

### 5.2 市场与 K 线

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-MKT-01 | P0 | 标的搜索、自选组和历史日线浏览 | 区分交易场所和交易对；支持指定日期、缩放、平移、十字光标 |
| FR-MKT-02 | P0 | 成交量、MA、EMA、MACD、RSI | 参数可配置；预热期显示为空；结果与选定参考实现对齐 |
| FR-MKT-03 | P0 | 交易和笔记叠加 | 点击标记打开关联记录，反向跳转恢复周期与时间范围 |
| FR-MKT-04 | P0 | 市场口径和异常展示 | 可识别复权、时区、过期行情、缺失数据和未完成 K 线 |
| FR-MKT-05 | P1 | 多周期、多图联动和基础绘图工具 | 支持时间同步、水平线/趋势线及持久化标注 |
| FR-MKT-06 | P2 | 实时推送与更多指标 | 按来源能力启用；明确延迟与授权状态 |

### 5.3 资产账本与统计

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-LED-01 | P0 | 记录期初、买卖、入出金、转账、费用、分红、利息和更正 | 事件可追溯，数量和资金变动一致；不能静默修改已入账历史 |
| FR-LED-02 | P0 | 多币种和统一估值 | 保留原币；USD/USDT/USDC 分开；缺汇率时不伪装完整总值 |
| FR-LED-03 | P0 | 成本批次、部分卖出、已实现/未实现损益 | 默认 FIFO；展示费用计入方式；剩余数量与成本正确 |
| FR-LED-04 | P0 | 组合范围内转账配对 | 全部资产视角不产生收益；单账户视角识别外部资金流 |
| FR-LED-05 | P0 | 总资产、负债、净资产和分类/账户分布 | 手工估值标注估值日期；估值过期与遗漏可见 |
| FR-LED-06 | P0 | 净投入、区间损益、费用和基础回撤 | 所有指标共享明确统计范围；费用只扣一次 |
| FR-LED-07 | P1 | TWR、MWR/XIRR、基准和币种影响分析 | 满足输入条件才计算；无解、多根或数据不足给出状态 |
| FR-LED-08 | P0 | 拆股和现金分红等基础公司行动 | 数量/成本按规则变更；与复权行情不重复计算收益 |
| FR-LED-09 | P1 | 账户风险观察 | 展示集中度、现金比例、单标的暴露；不把相关性当作确定风险预测 |

首版“基础回撤”针对有可靠估值序列的区间；存在外部资金流且无法构建可比净值序列时，不将资产余额回撤标为投资回撤。不同收益指标按金融计算文档实现。

### 5.4 交易日志

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-JRN-01 | P0 | Markdown 笔记、标签、搜索和自动保存 | 离线编辑；有保存状态；崩溃恢复到最近持久化版本 |
| FR-JRN-02 | P0 | 交易前/中/后结构化模板 | 支持判断、失效条件、计划风险、实际执行、情绪和结论 |
| FR-JRN-03 | P0 | 一篇笔记关联多个成交/计划/图表 | 支持分批建仓、减仓和双向跳转；关联对象更正后有提示 |
| FR-JRN-04 | P0 | 保存图表上下文和可选附件 | 存标的/场所/周期/时间/复权/指标；附件存在性和版本可追踪 |
| FR-JRN-05 | P1 | 按策略、情绪、行为标签复盘 | 展示样本数、缺失标签比例；不将未标记记录推定为某类 |

结构化字段大多可选。新建笔记以一句理由和关联交易为最小输入，避免记录负担阻碍使用。

### 5.5 K 线训练

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-TRN-01 | P1 | 随机历史片段、可隐藏日期与名称、逐步回放 | 数据接口受回放时钟约束；指标、列表和图表不能读取未来 |
| FR-TRN-02 | P1 | 初始资金、仓位、模拟委托与交易计划 | 支持市价/限价/止损/OCO；资金不足明确拒绝 |
| FR-TRN-03 | P1 | 费用与成交环境预设 | 费率、最低费用、按股收费、滑点和点差独立配置；保存版本 |
| FR-TRN-04 | P1 | 训练持久化、暂停、恢复和重放 | 输入、随机种子、数据及引擎版本相同则结果相同 |
| FR-TRN-05 | P1 | 训练报告 | 展示收益、回撤、风险、计划执行率、MAE/MFE及样本限制 |
| FR-TRN-06 | P1 | 训练中记录、结束后 AI 复盘 | 不操作可记录理由；回看历史不改写原训练结果，重试生成新运行 |

S2 首批交易环境只覆盖现货规则。maker/taker 只能在数据与成交模型支持时确定，否则显示明确假设。永续资金费、借券费和强平等待衍生品阶段。

### 5.6 策略研究

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-STR-01 | P1 | 表单式条件组合和日线批量扫描 | 支持逻辑组合、指标条件、标的池和扫描日期；输出命中理由 |
| FR-STR-02 | P1 | Python 策略接口 | 在独立工作进程运行；有超时、取消、错误定位和版本记录 |
| FR-STR-03 | P1 | 统一回测 | 与训练共用费用/撮合/估值口径；支持仓位、退出规则和基准 |
| FR-STR-04 | P1 | 实验比较与样本外评估 | 保存策略、参数、数据、标的池和运行版本；区分训练/验证/测试区间 |
| FR-STR-05 | P1 | 历史数据质量说明 | 当前成分股回溯扫描必须标注幸存者偏差；不冒充时点历史股票池 |
| FR-STR-06 | P2 | 节点式策略编辑器 | 使用有类型的策略表示；静态校验周期/依赖/数据可用性 |

扫描信号不等同于完整策略。创建回测前必须补齐成交时点、退出规则、仓位和成本。任意 Python 不承诺可逆转换为节点图。

### 5.7 AI 分析

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-AI-01 | P0 | 可配置的远程或本地模型连接 | 能力检测、连通性检查、凭据存储、超时与错误展示 |
| FR-AI-02 | P0 | 个人数据问答和复盘报告 | 数值来自工具计算；关键结论引用交易、笔记或统计证据 |
| FR-AI-03 | P0 | 当前页面上下文和数据范围 | 明确账户、期间、币种、可读笔记和模型；范围可调整 |
| FR-AI-04 | P0 | 证据与不足说明 | 引用可打开；显示样本数量/缺失；无法支持的因果判断不作为事实 |
| FR-AI-05 | P1 | 草拟标签、笔记和策略规则 | 生成预览，用户选择后保存；代码执行沿用脚本权限与运行限制 |
| FR-AI-06 | P0 | 本地功能独立于 LLM | 断网/未配模型时账本、图表和笔记正常使用；报告失败可重试 |
| FR-AI-07 | P0 | 可恢复的上下文与会话状态 | 范围/数据版本固定；压缩后权限与事实引用不漂移；取消/崩溃/恢复不混入旧运行或其他账户 |
| FR-AI-08 | P0 | UI 与 AI 共用能力接口和 OpenAI API 形式模型接入 | 同一 scope/版本结果一致；工具 schema、权限、错误、取消统一；Rust 客户端两协议、流式/取消与受控工具验证通过 |

首版 AI 仅调用只读业务工具，不接收任意 SQL 或系统命令执行权限，不承担账本数值计算。详情见 AI 设计。

## 6. 非功能要求

以下为目标，须在 S0 记录实际测试硬件与基准；未测量前不宣称达标。

| 编号 | 要求 | 初始验收目标 |
| --- | --- | --- |
| NFR-01 | 金融正确性 | 账本固定精度；参考场景逐项对账；不静默溢出或舍入 |
| NFR-02 | 可追溯 | 报告记录数据、计算和口径版本；历史更正后旧报告提示过期 |
| NFR-03 | 桌面响应 | Windows 11、16 GB RAM、SSD 基准机；本地首屏目标 ≤3 s；常规交互 P95 ≤100 ms |
| NFR-04 | 图表与表格 | 10 万条交易使用虚拟列表；10 万根历史 K 线按窗口加载；1000 根可见 K 线交互目标 ≥50 FPS |
| NFR-05 | 长任务 | 导入/扫描/回测有进度与取消；点击取消后 UI ≤1 s 响应，后台目标 ≤5 s 终止或进入终止处理中 |
| NFR-06 | 恢复 | 导入、入账事务原子提交；崩溃不出现半笔事件；备份恢复可校验 |
| NFR-07 | 平台 | Windows 首发；架构兼容 macOS/Linux；各平台经过打包验证后再承诺支持 |
| NFR-08 | 可维护 | 依赖锁定、来源与许可证记录；模块测试不依赖桌面窗口或真实账户 |
| NFR-09 | 可访问与本地化 | 中文优先，文案可国际化；键盘操作、焦点、缩放和涨跌配色可用 |
| NFR-10 | 隐私边界 | 默认本地保存；模型发送范围可见；常规日志不保存用户金融正文 |

## 7. 首版验收与成功标准

首版以工作流成功为准：用户导入一个有期初、买卖、费用、分红和转账的账户样本，能够解释余额、持仓、成本及区间变化；任一统计可追溯来源；任一成交可跳转 K 线与笔记；AI 报告引用同一批数据；重启与备份恢复后结果一致。

美股与加密现货至少各完成一个完整样本。发现数据缺口时能明确定位并补全，不能依靠隐藏错误来完成演示。首版不以策略收益率或 AI 推荐盈利率作为验收指标。

具体测试样本、需求映射和发布门槛见 [实施路线](../engineering/delivery-plan.md)。
