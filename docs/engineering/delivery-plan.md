# DELTA 实施路线与验收计划

版本 0.2 · 2026-09-26 · 所有产品条目为待实现；当前执行与角色见 [状态](../delivery/status.md)。

## 1. 交付方式

采用有退出条件的阶段，不在未知团队规模、可投入时间和数据权限下承诺日历工期。每个阶段交付可运行、可验证的用户功能；原型结束后再根据实测工作量排期。

采用 A 计划/审核、B 连续实现的长计划。技术门槛通过后继续同轮业务闭环，不按每个验证包交回；文档和接口只是实现依据，不能替代运行证据。

整体演进：S0 验证必要基础 → S1 资产复盘 MVP → S2 基本训练 → S3 基本策略，形成全部核心模块的基本功能后，再反复选择反馈最高的增强项。各阶段也可以小循环修正，不能以高级优化拖延下一个基本功能，也不能跳过当前金额/权限/恢复的必须门槛。

测试投入优先覆盖金额、数量、现金流、未来数据边界和恢复等高影响逻辑。一般文案/布局调整以人工检查为主，不编写只重复实现细节的测试。

## 2. S0：验证桌面与数据路径

| 工作包 | 产出 | 退出条件 |
| --- | --- | --- |
| S0-01 桌面骨架 | GPUI 窗口、导航、表格、Dock、中文编辑 | Windows 干净机器启动；中文输入/125%与150%缩放可用 |
| S0-02 图表验证 | 日线、指标子图、标记、跳转、回放截止原型 | 明确原生或 WebView 路径；关键交互与性能达标或有可接受修正计划 |
| S0-03 存储验证 | SQLite 迁移、事务导入、备份恢复样例 | 崩溃/失败不会产生半笔事件；恢复校验通过 |
| S0-04 数据与日历 | 美股/加密各一组真实历史样本、来源能力表 | 时区、精度、公司行动和缺失规则可解释；实际授权路径明确 |
| S0-05 指标与 Python | TA-Lib 对照、工作进程与打包试验 | 决定首版指标后端；无手工开发环境依赖的发布路径 |
| S0-06 AI 运行时与统一接口 | Rust 模型客户端、OpenAI 双协议、范围/工具/会话/压缩/恢复 | 假端点上的真实 Rust 双协议集成、工具白名单和状态恢复通过；真实端点单独验收 |

原型只实现需要验证的路径，避免生成大量未使用框架。S0-02 的图表问题不阻塞账本核心；S0-04 的账号权限问题不阻塞离线样本开发，但阻塞相关在线数据功能的发布承诺。

## 3. S1：真实账户复盘闭环

按纵向功能推进：

1. 建资料库/账户 → 导入预览 → 事件校验 → 正式入账 → 余额核对。
2. 期初、买卖、费用、转账、拆股、分红 → 持仓成本 → 估值与损益解释。
3. 历史日线/指标 → 成交标记 → 笔记关联 → 从统计跳回证据。
4. 只读分析工具 → 一个模型连接 → 带引用的复盘报告。
5. 备份/导出/恢复 → 干净 Windows 安装 → 完整验收。

每步使用同一组去标识样本，避免只做互不关联的页面演示。所有 P0 完成后才能把 S1 标为完成；单个未准备好的在线来源明确显示未接入。

S1 完成标准：美股与加密现货各一个账户场景完成导入、核对、图表和笔记复盘、AI 证据问答，并通过重导、更正、重启和恢复检查。

## 4. S2：K 线训练

工作顺序：统一回放时钟 → 订单/费用模型 → 逐步推进与资金预留 → 训练持久化 → 执行质量报告 → 结束后 AI 复盘。

可并入账户 API 同步和完整收益指标，但它们是独立工作包，不能改变训练核心的交付边界。S2 先只覆盖现货；衍生品收费字段不等于衍生品功能已完成。

退出条件：相同种子、数据与操作得到一致的确定性结果；未来数据隔离检查通过；训练恢复不重复成交；费用和跳空规则有手算对照；真实资产未受影响。

## 5. S3：策略研究

工作顺序：有类型的条件表示 → 日线扫描 → 完整策略参数 → Python 接口 → 共享模拟引擎回测 → 实验版本与比较 → 样本外/滚动验证。

首批条件包括价格/成交量阈值、均线交叉、区间突破及逻辑组合。规则图限定为可静态校验的表达式依赖图；策略执行状态通过明确状态对象表示。任意自由节点编辑器不属于本阶段前置条件。

退出条件：指定数据集上扫描命中可解释，回测可以重现，手动训练和策略输入相同订单序列时结果相同，基准可比，标的池与历史可得性局限可见。

## 6. S4：按价值排序扩展

候选依次由用户实际需求决定：更多账户接口、小时/分钟周期、实时行情、多图联动、节点编辑器、复杂资产、衍生品、跨平台发布、多端同步。任何项需补充自身业务规则和验收，不能只接入 SDK 就宣布支持整个市场。

## 7. 需求到阶段与设计的映射

逐条 FR/NFR 的唯一映射见 [traceability.json](../delivery/traceability.json)，包含阶段、设计和 AC；当前均为 planned。摘要：P0 在 S1（相关技术验证在 S0），训练和账户同步/高级分析 P1 在 S2，策略 P1 在 S3，P2 在 S4。不得把“P0 已映射”解释为“已实现”。

新增需求必须补实际阶段、设计及可判断的验收场景；没有验收定义的扩展只保留在后续循环，不能承诺完成。

## 8. 金融与完整工作流验收样本

以下场景形成可版本化的 fixtures。正式实现时把手算期望值与输入文件一起保存，避免只用实现自身生成期望值。

| 编号 | 场景 | 必须得到的结果 |
| --- | --- | --- |
| AC-01 | 相同文件重导；同秒同价两笔独立成交；跨文件重叠 | 重导幂等；真实独立成交保留；不确定重复进入人工核对 |
| AC-02 | 初始 2000，买 10×100 费1，卖4×110 费1，期末价105 | 现金1438、数量6、成本600.6、已实现38.6、未实现29.4、总损益68 |
| AC-03 | 已入账成交金额更正 | 原记录可追溯；新投影只生效一次；旧报告提示过期 |
| AC-04 | 两账户转账1000、另收手续费2 | 全组合本金不产生收益；费用损益-2；单账户按范围识别外部资金流 |
| AC-05 | 2:1拆股与现金分红 | 拆股总成本不变；分红只记一次；与复权/基准口径一致 |
| AC-06 | 缺汇率、缺价格、成本未知、稳定币偏离1美元 | 缺项显式；不伪造完整收益；稳定币按实际独立资产估值 |
| AC-07 | 组合期初1000，期中投入1000，市场不变，期末2000 | 区间损益0；条件完整时TWR和XIRR为0；不能显示投资收益100% |
| AC-08 | 一计划关联多次加减仓、笔记跳图表 | 关联数量不超额；周期/时间/复权/指标可恢复 |
| AC-09 | 自动保存、导入中断、一致性备份与恢复 | 无半笔事件；保存状态诚实；数据与附件引用恢复一致 |
| AC-10 | AI 解释 AC-02 并查询不足样本 | 数值68及分项正确；证据可打开；样本不足明确说明 |
| AC-11 | 向未来行情注入极端哨兵值，高周期未闭合 | 当前指标、图表、订单和策略输入不受未来影响 |
| AC-12 | 同根触及止盈/止损、跳空穿过止损 | 执行声明的歧义政策；跳空按实际可用价假设；不保证止损价 |
| AC-13 | 按订单最低收费的多个部分成交 | 最低费层级正确、舍入可对账；费用不重复扣除 |
| AC-14 | 训练暂停/恢复/重新尝试 | 恢复不中断状态、不重复成交；重新尝试生成新run；真实账本不变 |
| AC-15 | 相同策略、数据、参数、种子重复运行 | 确定性结果一致；浮点在固定容差内；不同版本明确分开 |
| AC-16 | Python 超时/崩溃/取消、无效策略草稿 | 主程序保持可用；结果不标成功；无效草稿不能成为运行版本 |
| AC-17 | API 限流、分页重试、余额与流水不一致 | 游标只在提交后推进；重传不重复；差异不自动抹平 |
| AC-18 | XIRR 无根/多根、零亏损、标签不完整、现金暴露集中 | 指标有明确状态；样本/覆盖可见；不输出误导的普通数值 |
| AC-19 | 笔记含越权指令，模型捏造引用，模型离线 | 权限不扩大；无效引用被拦截；本地工作流可继续 |
| AC-20 | 导出、删除资料库、删除附件、诊断日志 | 导出开放格式完整；删除范围可确认；无意外残留引用或秘密日志 |
| AC-21 | 美股夏令时、半日市与加密日线时区 | 时间切分正确；休市与缺数据区分；不会错移一根K线 |
| AC-22 | BTC/USDT买卖，用第三资产支付费用，跨账户搬移持仓 | 三种资产数量与成本可对账；缺费用估值进入待补全；搬移不生成虚假收益 |
| AC-23 | UI 与 AI 在同范围/修订查询；重复/未知工具和错误协议 | 数值、质量、证据一致；schema/范围/错误/幂等遵守统一契约 |
| AC-24 | Rust 多轮会话、原子压缩、恢复、换账户/模型、取消和晚到事件 | 原 scope 与事实引用不漂移；旧代次不能污染新运行；故障不标成功 |
| AC-25 | Rust 工具/配置隔离探针与 OpenAI 两种协议 | 无任意文件/终端工具；不继承外部配置；两适配均验证工具配对、流式终态、部分流不重放、取消、鉴权和模型能力 |
| AC-26 | 首屏/交互/列表/图表与取消的固定规模基准 | 按 NFR-03～05 实测并报告硬件、次数、分位数；未测不宣称达标 |
| AC-27 | Windows 干净安装、中文输入、键盘/缩放、离线、依赖来源 | 安装可运行且无需开发环境；范围内操作可用；锁定与许可清单齐全 |
| AC-28 | 标签复盘与未来 AI 草稿接受 | 统计显示样本/缺标签，草稿经用户接受及正常命令保存；不得直接改账本 |
| AC-29 | S4 多周期实时、更多指标/节点扩展 | 逐新增能力补专门用例后验收；拒绝不支持能力；记录来源授权、延迟、类型与周期校验 |

AC-13 如初始模拟器未实现部分成交，先用导入分笔成交和费用规则单元样本验证；不能以未开放部分成交为由省略计费层级模型。

S1 必过 AC-01～10、AC-19～27 中对应首版能力的场景。AC-07 的精确 TWR/XIRR、AC-18 和训练/策略场景随阶段开放，但 S1 已必须正确区分资金流和收益。

## 9. 测试与发布门槛

- 领域：手算样本、数量/金额/成本守恒性质测试，复杂更正和转账回归。
- 指标/日历：固定参考实现输出、预热与缺失规则、夏令时/半日市对照。
- 存储：幂等、事务失败、迁移、备份恢复与附件一致性。
- 适配器：匿名录制响应或公开样本测试分页、缺字段和错误；有条件时小规模真实只读连通验证。
- 桌面：首次导入、图表跳转、笔记编辑、AI 引用和恢复的关键流程；输入法/缩放人工检查。
- 性能：固定硬件记录数据量、耗时、内存与帧率，按 PRD 目标验证；不是仅声明“Rust 很快”。

正式提交应用代码后，持续集成至少执行格式、lint、领域/存储测试和 Windows 构建；Rust 模型模块增加双协议、范围、压缩与生命周期验证，Python 启用时加入 schema/指标对照。实际命令随工程落地再添加，当前文档不声称已运行任何应用测试。

发布前，P0 的金额错误、未来数据越界、账户数据混入、损坏恢复和权限泄露必须清零。其他已知限制写入用户可见说明，并与尚未承诺的功能区分。

## 10. 确认与待处理入口

已确认基线和设计默认值分别见 [决定记录](../decisions/confirmed-decisions.md)。用户问题、开源适配缺口、人工/真实配置与后续优化只维护在 [集中事项台账](../decisions/open-questions.md)。

真实账号/数据/模型缺失不阻塞合成闭环，但阻塞对应真实验收及完整 S1 退出；B 完成代码和自动验证后，A 集中提供具体可操作的人工包。正式开发计划入口见 [当前状态](../delivery/status.md)。

## 11. 主要风险与处置

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 图表需要大量定制 | 吞噬功能开发时间 | S0 限定验证范围，必要时复用 Web 金融图表 |
| 行情授权/历史数据不足 | 回测不完整、在线功能受阻 | 数据能力清单、可导入格式和离线样本；真实接入单独验收 |
| 财务规则跨模块漂移 | 页面与报告数值冲突 | 单一领域核心、口径版本和手算样本 |
| Python 发布复杂 | 首次安装失败 | 独立进程、锁环境、干净机器验证、按需启用 |
| 功能范围膨胀 | 长期没有可用版本 | S1 完整闭环优先，扩展需新增验收 |
| 上游快速变化 | 构建/行为不稳定 | 稳定版本锁定、薄适配层、升级回归 |
| AI 说服力超过证据 | 错误复盘 | 只读工具、数值与引用验证、样本限制 |

下一步按当前计划从必要 S0 验证连续推进 S1/P0 代码闭环；受阻部分隔离，领域、接口与固定样本继续。A/B 交接不要求实际并行执行，默认同一工作区只有一位写入者。
