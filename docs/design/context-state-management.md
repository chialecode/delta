# AI 上下文、会话与运行状态

版本 0.3 · 2026-09-26。按 D-08 使用 Rust 应用编排与 SQLite 会话仓储，通信由 [模型客户端](rust-model-client.md)承担。参考 Codex 的历史配对与压缩设计，不移植编码工作流。

## 1. 状态所有权

| 内容 | 所有者/持久化 | 恢复原则 |
| --- | --- | --- |
| 账本、笔记、行情版本、确定性结果与证据 | Rust 应用服务 / SQLite 与版本文件 | 业务事务和数据修订为真相 |
| session/run、范围快照、预算、连接和 generation | Rust / ai_session、ai_run | 不从模型摘要恢复授权 |
| 原始转录、工具调用/回执、协议保留项 | Rust / ai_message、ai_tool_call | 按 session/turn/sequence 排序；正常写入追加，删除/迁移走显式生命周期 |
| 上下文摘要、源区间、活动历史入口 | Rust / ai_checkpoint | 事务切换检查点；保留原历史，记录模型/模板/摘要版本 |
| 页面和流式展示 | UI 投影 | 从已提交状态重建，未落盘文本不伪装可恢复事实 |
| 用户明确保存的偏好/长期笔记 | 设置与 journal | 来源/修订可追溯；无自动长期记忆代理 |

所有会话存储按资料库隔离，凭据只存引用。模型客户端是无会话仓储的传输组件，不另写一份可编辑转录。原始转录也属于敏感用户数据，纳入备份/删除/授权范围；不把模型输出变成金融事实。

## 2. 范围与上下文组装

`ContextSnapshot` 包含 library/session/run、account/member snapshot、时间范围、币种、ledger/market/journal/calculation 版本、工具目录哈希、模型路由/能力、允许的笔记、历史 visible_until（训练才有）、预算和用户同意的数据范围。

每次运行先冻结范围，获得可恢复分析快照，再组装固定系统约束→范围/质量→确定性结果摘要→必要证据→最近完整回合→当前问题。用户问题、笔记与外部文本都是 data，不能更改权限。页面切换不扩大在途运行。

改变账户/授权笔记范围、协议、模型或数据修订时开启新 run/generation；缩小权限或换账户时使用干净上下文，旧摘要与 opaque 项不得随之携带。模型/协议切换默认创建新上下文，必要业务摘要由宿主重建，不直接转发供应商私有项。

工具默认聚合与分页；中文搜索先验证 FTS/关键词。省略材料记录覆盖率/缺项。运行前持久化最小只读分析快照或不可变修订引用；不能在整个网络调用期间持有 SQLite 长事务。旧快照缺失明确拒绝恢复，不能换成 latest 冒充原分析。

## 3. 工具循环与历史完整性

Rust AgentRuntime 从宿主注册的只读能力生成工具目录，通过 ModelClient 获取完整工具请求。工具名称/schema/scope/run/generation/预算均经 AnalysisToolGateway 再校验，校验后才执行；不注册任意文件、shell、SQL 或下单能力，不读取开发工具的全局配置、指令和凭据。

以 `(run_id, tool_call_id)` 和参数摘要记录调用；同 ID 同参数返回已有回执，同 ID 异参数拒绝。调用及完成回执持久化，模型上下文按完整 tool call/output 组装，不能只截掉一侧。中断的调用保持 interrupted；需要发送失败结果给下一回合时明确为失败并保留依据，不伪造执行成功。

首轮工具顺序执行；任何业务写操作未来必须另定义授权和幂等协议。只读查询也绑定原数据快照。对外输入中的 call_id 不是权限证明。

## 4. 压缩与预算

DELTA 的 Rust ContextManager 负责有限范围的摘要/检查点编排，模型总结通过同一 ModelClient 调用。参考 Codex 的完整回合裁剪、历史配对与上下文重建，不调用供应商专有 compact endpoint。R1 仅做线性会话和显式检查点，不建对话树编辑器或自动长期记忆系统。

预算包括输入窗口、输出预留、工具结果/次数、摘要调用、耗时和费用估计。窗口未知需配置/探测；tokenizer 采用已验证匹配库，无法精确匹配时记录保守估计，服务端超限可控失败，不能声称精确 token 数。

压缩流程：冻结可压缩的旧完整回合和内容哈希→保留系统约束/范围/最近完整回合→在相同授权和预算下生成摘要→验证结构、源范围与引用→短事务写入 ai_checkpoint 并切换活动入口。记录摘要模型/协议、提示模板版本、源消息区间、输入哈希和用量。摘要作为不可信历史内容插入，不能提升为系统指令。

原始消息、工具回执和金融结果不删除；金额、权限和证据不能仅存在摘要。取消、失败或数据库提交失败不切换活动检查点。并发撤权/generation 变化使待提交摘要失效。压缩后重新估算窗口、重新从宿主构建 scope 和工具白名单；仍超限则说明上下文不足，不循环压缩到丢失约束。

## 5. 运行状态与故障

```text
created -> preparing -> running -> validating -> succeeded
                      |          |             -> failed
                      +-> cancelling -> cancelled
任意非终态 + 宿主崩溃/不可恢复任务中断 -> interrupted
```

compacting 是 running 子状态。模型请求完成并不代表整个 run 完成；工具回合正常结束、引用/数值验证及报告事务全部完成后才 succeeded。重试、压缩和工具调用消耗同一个 run 预算。

转录按完整消息/工具回合提交；流式草稿如需持久化单独标 partial，不能伪装已完成 assistant 消息。宿主重启将遗留运行标 interrupted，保留已提交转录/工具回执。用户重试创建新 run/generation，默认引用原快照并重检授权；不自动重发可能已计费的半流请求。

关闭/撤权先失效 generation 并停止接纳新工具，再取消网络/退避/压缩任务和句柄。迟到事件不能修改新运行。无正常终态的报告保持失败/中断；已观测用量保留，缺失用量记未知。

## 6. 连接与配置

连接使用显式协议、base URL、model ID、credential_ref、上下文窗口、能力和超时。两种协议的最小能力与配置由 [模型客户端](rust-model-client.md)定义；能力不足明确显示，不能按品牌猜测。调用仅发送用户指定的范围，附件默认不发送，日志不写正文与密钥。

## 7. 验收边界

必须覆盖多轮持久恢复、强制压缩前后 scope/引用不漂移、压缩提交失败、账户切换、取消和迟到事件、宿主崩溃、完整工具配对、半流不重放、未知工具/恶意笔记、两协议与小窗口失败。固定假服务通过真实 Rust 客户端验证；真实配置另作有界只读测试。恢复通过不等于自然语言逐字可复现。
