# ADR-0001：文档约束与 A/B 交付

日期：2026-09-26；状态：accepted（D-01～04、D-07）；责任：A／维护者。

## 问题

既有需求/设计覆盖较全，但缺少唯一正本范围、实际状态、集中事项、逐需求追踪、运行证据与跨 Agent 接续协议。聊天中的选择容易丢失，阶段优先级容易被误解成已实现。

## 决定

根 AGENTS 作为工作入口；产品、设计、工程规则、决策、交付、证据分层。以文档登记、稳定编号和机械检查维护可发现性；语义仍需审核。保留原 FR/NFR/AC 和金融口径，后续变更按职责更新。

A 完成开源比较和可连续执行的长计划，B 实现全部可执行范围并自审，A 集中审核。交接以仓库文件和 Git 版本，双方结束提供可复制 prompt；待决/开源/人工/后续项集中管理。可确定局部修复由 A 收尾，大缺口整批返工。

## 替代与影响

未采用一个巨大 AGENTS（难按需阅读）、仅聊天规划（不可接续）、每文件审批（增加往返）、完整企业文档流程（超出 MVP）。登记与追踪增加少量维护成本，由校验器发现漂移，不为形式补无关模板。

本地 Git 首空 README、次文档基线，后续计划独立提交。应用实现、真实服务及人工验收不在文档框架完成声明内。
