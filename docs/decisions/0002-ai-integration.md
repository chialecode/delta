# ADR-0002：参考 Codex 自研 Rust 模型客户端

日期：2026-09-26；状态：accepted（用户 D-08 确定方向，具体实现待验）；责任：A 方案/审核、B 实施。本文按最新决定重写，适用于清理后的文档框架。

## 问题与选择

用户要求保持 Rust + Python，并参考 Codex 官方 Rust 实现自研模型客户端。OpenAI API 形式接口方向保持。采用 **Rust ModelClient + Rust AgentRuntime + SQLite 会话仓储**：客户端处理通信，应用层处理业务工具、上下文、预算和证据；Python 用于指标/日历/研究等已有生态能力。

参考 `openai/codex` 固定提交 `c7e80f873f67dbef58206b9d4f3c60e9d556eb16` 的客户端、SSE、重试、历史配对和压缩模块，来源/许可见 [研究证据](../evidence/2026-09-26-codex-rust-research.md)。不整体 fork 编码平台、不依赖 app-server、不默认继承其权限/工具/配置。复用成熟网络、序列化和流解析库，DELTA 只实现自己的窄模型协议和上下文整合。

## 比较与代价

| 方案 | 价值与代价 | 本轮结论 |
| --- | --- | --- |
| 参考官方 Rust 源码，围绕窄 ModelClient 自研 | 与用户栈和业务状态一致；需要自己维护协议测试、流式拼接、取消、兼容和升级 | 已选方向；边界见模型客户端设计 |
| 直接引入 Codex 内部 crates 或完整 app-server | 现成运行体系；内部 workspace 耦合、编码场景及认证/发布边界过大 | 仅作参考，不作为产品运行依赖 |
| Rust 通用模型库（如 Rig） | 可复用部分 provider 接入；能力和状态格式仍需适配 | 未来维护成本高时比较窄层替换；本轮不并行建设第二套主客户端 |
| Python 编排平台 | 工作流生态丰富；会增加跨语言会话所有权和同步成本 | Python 保留分析/研究职责，本轮模型编排留在 Rust |

## 协议、状态与验证

R1 必须实现 Responses 与 Chat Completions 两个显式适配并分别通过受控端点验证。OpenAI 官方连接推荐 Responses，第三方按实际能力配置；不静默回退。真实调用只在授权端点/模型上验证，缺配置不阻塞受控测试。

转录、工具调用/回执、run 和 checkpoint 由 Rust 在 SQLite 中持久化。摘要与原始历史分开；范围、金融事实和证据由业务仓储保证。保留完整工具配对、取消代次和压缩原子提交，避免会话恢复丢失范围。

POC-04 验证真实 Rust 客户端到假服务的流式、两协议、工具白名单、部分流不重放、压缩/中断/恢复；Windows 分发与真实端点另验。失败登记 OSS-07/08，修复受影响窄层，独立业务继续。

## 维护与退出

用户明确授权此自研范围，不再要求 B 为同一方向反复审批。HTTP/TLS/异步/SSE parser 仍优先开源复用；不得扩展成通用 Agent 平台。复制源代码时记录提交、片段、变更和适用许可，参考升级按协议回归结果决定。

原模型方案没有已提交产品数据迁移需要；现场旧脚手架先核对归属，不纳入新依赖/构建/交付，也不覆盖他人未提交工作。以后有实际会话后，替换须迁移或导出，不能丢记录。
